# 01. 何を作るか（要件定義）

**この文書は抽出物。** 正（`event-storming/` と `features/`）から、非エンジニアでも
読める言葉に書き直したもの。中身は持たず、詳しい経緯は正を見る。手で直さない。
正が変わったら作り直す。なぜ作るかは [00-why.md](00-why.md) を見る。

## 登場人物

- **幹事**: 車割り(誰がどの車に乗るか)を決める人。**この道具の対象外。** 車割りが
  終わった結果だけを前提にする。
- **運転者**: 車割りが決まったあと、出発地・目的地・到着希望時刻を決め、同乗者に
  リンクを共有する人。この道具の主役。
- **同乗者**: 運転者の車に乗る人。共有されたリンクから、自分の拾ってもらう場所を入れる。

## 対象の範囲

- **誰のため**: 運転者のため。人を迎えに行ってから目的地へ向かう、運転者自身の
  計画作りを楽にする。
- **v1 のゴールはゴルフの送迎。**
- 1台の車の中だけで完結させる。車の台数や、複数台の車同士の調整は扱わない。
- 1台あたりの同乗者は、2〜7人程度を想定。

## 使い方の流れ

1. 運転者が、出発地・目的地・到着希望時刻を入れて計画を作る。
2. 運転者が、計画の**リンクを同乗者に共有する**(共有の手段は問わない)。
3. 同乗者がリンクを開くと、**今のルートが見え、自分の拾ってもらう場所を追加できる。**
4. 場所が追加されるたびに、順番と時刻が自動で出し直される。
5. 当日は、運転者も同乗者もリンクを開いて、最新の順番と時刻を見る。

## 機能要件

### 1. 運転者が送迎計画を作る

運転者は、出発地・目的地・到着希望時刻の3つを入れるだけで、送迎計画を作れる。

- 出発時刻は、到着希望時刻から自動で逆算される。
  (例:出発地から目的地まで40分かかり、到着希望時刻が7:00なら、出発時刻は6:20になる)
- 同乗者がいる場合、迎えに行く順番は、一番早く回れる順番に自動で決まる。運転者が
  順番を考える必要はない。
- 各地点では、人を乗せるのに5分かかるものとして計算する(人や地点ごとには変えない)。
- 同乗者が1人もいなくても、計画は作れる。

### 2. 同乗者が拾ってもらう場所を追加する

同乗者は、運転者から共有されたリンクを開くと、今のルートを見ながら、自分を
拾ってもらう場所を追加できる。

### 3. 同乗者が拾ってもらう場所を変える

同乗者は、一度入れた場所を、あとから変更できる。

### 4. 同乗者が拾ってもらう予定を取り消す

同乗者は、乗れなくなったとき、自分の予定を取り消せる。

### 5. 運転者が出発地を変える

運転者は、出発地をあとから変更できる。

### 6. 運転者が目的地を変える

運転者は、目的地をあとから変更できる。

### 7. 予定が終わったら、同乗者の情報を消す

同乗者の拾ってもらう場所は個人情報なので、予定が終わったら自動で消える。
**「予定が終わった」の具体的なタイミングは、まだ決まっていない。**

### 再計算のルール(2〜6に共通)

場所や地点が変わったとき、いつ順番と時刻を計算し直すかのルール。
**地点が変わったときだけ。人が変わっても、地点が同じなら再計算しない。**

| 起きたこと | 再計算するか |
|---|---|
| 同乗者が増えた・減った | する |
| 同乗者が場所を直した(同じ人、違う場所) | する |
| 運転者が出発地を変えた | する |
| 目的地が変わった | する |
| 同じ場所のまま、乗る人が入れ替わった | **しない** |
| 日付が近づいた・当日の朝になった | **しない** |

当日の渋滞で時刻がずれることはある。それでも、一番大事なのは**計画を立てるときと、
同乗者が場所を足すときの計画**。日ごとや当日朝の再計算は要らない。

## 非機能要件

- **スマホで使う前提。** 運転者も同乗者もスマホでリンクを開く。
- **同乗者はなるべく手間なく入れる。** リンクを開くだけで、場所を追加できるところまで行ける。
- **住所は、予定が終わったら消す。** 同乗者の住所は個人情報なので、必要な間だけ持つ。
- **いずれはゴルフに限らず使えるようにする。** レンタカーでの送迎、イベントの送り迎えなど、
  「何人か拾ってから目的地へ向かう」場面全般。
  v1 で汎用の機能は作らないが、**ドメインの言葉やデータの形をゴルフ固有にしない**
  (「ゴルフ場」ではなく「目的地」、「ラウンド」ではなく「予定」のように)。

## やらないこと

- 車割りそのもの(誰がどの車に乗るか)を決めること。幹事が別の手段で先に決めている前提。
- 複数台の車同士の調整(「A車とB車、どちらが先に出るか」など)。
- 運転者による、お迎えの順番の手動の並べ替え。順番はアプリが決める。
- 人や地点ごとに積み込み時間を変えること。
- 出発時刻から順に計算すること。到着希望時刻からの逆算だけ。
- 日ごとや当日朝など、時刻をきっかけにした再計算。
- 変更を能動的に知らせる仕組み(プッシュ通知など)。**ページを開けば最新が見える**で足りる。
- 復路(帰りの送り)の計画。
- 割り勘や費用の計算。

範囲を広げたくなったら、新しい Issue にする。

## まだ決まっていないこと

- 「予定が終わった」の具体的なタイミング(到着希望時刻を過ぎたらすぐか、その日の
  終わりか、数日後か)
- 共有リンクを知っている人なら、誰でも場所を追加・変更できてよいか
- 同じ場所(同じ住所)を、2人の同乗者が重ねて登録できてよいか
