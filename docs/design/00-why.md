# 00. なぜ作るか

## 背景

ゴルフに行くとき、複数人で車に乗り合わせる。幹事が車割り(誰がどの車に乗るか)を決めたあと、
各車は4人程度のチームになり、その中の「運転者」が決まる。**この道具が対象にするのは、ここから先。**

運転者は、同乗者の家を回ってから目的地(ゴルフ場)へ向かう必要がある。今はだいたいこういう流れになっている。

1. LINE で、運転者が同乗者に住所を聞く(一人ずつ)
2. 聞いた住所を、運転者が Google Map に手で打ち込む
3. 経由地の順番と、それぞれを何時に出るかを、運転者が頭で計算する

これで前日までに「何時にどこへ出発するか」が決まる。当日はその予定で動く。

## 課題(ペイン)

- **住所を聞いて打ち込むのが面倒。** 人数が増えるほど、LINE のやり取りと手入力の回数が増える。
  聞き漏れや、住所の打ち間違いも起きる。
- **順番と時刻を頭で計算するのが面倒で、ミスが起きやすい。** 積み込みにかかる時間を各地点に
  足し忘れたり、経由の順番を取り違えたりする。
- **同乗者の顔ぶれが決まったあとで変わると、計算をやり直すのが特に面倒。** 誰かが
  新しく乗ることになった、誰かが乗れなくなった、住所を間違えて直した——
  こういう変更が入るたびに、運転者がもう一度頭で計算し直す必要がある。
  **やり直し忘れると、古い計画のまま当日を迎える。**

3つ目が一番困っている。1つ目と2つ目は「毎回面倒」だが、3つ目は「ズレに気づかないまま
当日を迎える」という実害につながる。

## 目指す状態

- 同乗者が、自分の住所を**自分で**入れられる。運転者が聞いて打ち込む必要がない。
- 迎えに行く順番と、各地点を出る時刻が、**自動で**出る。頭で計算しない。
- **出発地・経由地・目的地のどれかが変わったら、自動で再計算する。** 運転者も同乗者も、
  ページを開けば常に最新の順番と時刻が見える。運転者が「計算をやり直す」ことを覚えておく必要がなくなる。

3つ目が、この道具の本命の価値。1つ目と2つ目は、3つ目を実現するための土台。

### 再計算のきっかけ

**地点が変わったときだけ。人が変わっても、地点が同じなら再計算しない。**

| 起きたこと | 再計算するか |
|---|---|
| 同乗者が増えた・減った(経由地が増減) | する |
| 同乗者が住所を直した(同じ人、違う地点) | する |
| 運転者が出発地を変えた | する |
| 目的地が変わった | する |
| 同じ地点のまま、乗る人が入れ替わった | **しない** |
| 日付が近づいた・当日の朝になった | **しない** |

当日の渋滞で時刻がずれることはある。それでも、一番大事なのは**計画を立てるときと、
同乗者が地点を足すときの計画**。日ごとや当日朝の再計算は要らない。

## 想定する使い方

- **誰のため**: 運転者のため。人を迎えに行ってから目的地へ向かう、運転者自身の計画作りを楽にする。
- **v1 のゴールはゴルフの送迎。**
- 1台の車の中だけで完結させる。車の台数や、複数台の車同士の調整は扱わない。
- 1台あたりの同乗者は、2〜7人程度を想定。

## 非機能要件

- **いずれはゴルフに限らず使えるようにする。** レンタカーでの送迎、イベントの送り迎えなど、
  「何人か拾ってから目的地へ向かう」場面全般。
  v1 で汎用の機能は作らないが、**ドメインの言葉やデータの形をゴルフ固有にしない**
  (「ゴルフ場」ではなく「目的地」、「ラウンド」ではなく「予定」のように)。

## 登場人物(仮)

- **幹事**: 車割りを決める人。**この道具の対象外。** 車割りが終わった結果だけを前提にする。
- **運転者**: 車割りが決まったあと、自分の車の出発地を決め、同乗者を迎えに行く順番と時刻を決める人。
  **この道具の主役。**
- **同乗者**: 運転者の車に乗る人。自分の住所(拾ってもらう地点)を入れる。

## やらないこと

- 車割りそのもの(誰がどの車に乗るか)を決めること。幹事が別の手段で先に決めている前提。
- 複数台の車同士の調整(「A車とB車、どちらが先に出るか」など)。
- 日ごとや当日朝など、時刻をきっかけにした再計算。
- 変更を能動的に知らせる仕組み(プッシュ通知など)。**ページを開けば最新が見える**で足りる。
- 復路(帰りの送り)の計画。
- 割り勘や費用の計算。

範囲を広げたくなったら、新しい Issue にする。

## Hotspot(疑問・揉めごと)

- **積み込み時間**(各地点で人を乗せるのにかかる時間)をどう扱うか。全員一律か、人や地点ごとに変えるか。
  → Day2 のイベントストーミングで決める。
