# 00. なぜ作るか

## 背景

ゴルフに行くとき、複数人で車に乗り合わせる。誰か1台の車に「運転者」がいて、
ほかの「同乗者」を自分の家まで迎えに行ってから、目的地(ゴルフ場)へ向かう。

このとき、今はだいたいこういう流れになっている。

1. LINE でグループを作る
2. 運転者が、同乗者に住所を聞く(一人ずつ)
3. 聞いた住所を、運転者が Google Map に手で打ち込む
4. 経由地の順番と、それぞれを何時に出るかを、運転者が頭で計算する

これで前日までに「何時にどこへ出発するか」が決まる。当日はその予定で動く。

## 課題(ペイン)

- **住所を聞いて打ち込むのが面倒。** 人数が増えるほど、LINE のやり取りと手入力の回数が増える。
  聞き漏れや、住所の打ち間違いも起きる。
- **順番と時刻を頭で計算するのが面倒で、ミスが起きやすい。** 積み込みにかかる時間を各地点に
  足し忘れたり、経由の順番を取り違えたりする。
- **前日までの見積りが、当日ズレる。** 典型的にはアクアラインの渋滞。見積もった時刻に出発しても、
  同乗者を待たせたり、目的地への到着が遅れたりする。**この見積りと実際のズレに、誰も対処していない。**
  気づくのは、だいたい渋滞にはまってからになる。

3つ目が一番困っている。1つ目と2つ目は「面倒」だが、3つ目は「当日に実害が出る」。

## 目指す状態

- 同乗者が、自分の住所を**自分で**入れられる。運転者が聞いて打ち込む必要がない。
- 迎えに行く順番と、各地点を出る時刻が、**自動で**出る。頭で計算しない。
- **出発の期日が近づいたら、渋滞を反映して再計算し、ズレが出たら全員に知らせる。**
  前日までの見積りのまま当日を迎えることがなくなる。

3つ目が、この道具の本命の価値。手作業では絶対にできない部分で、ここができて初めて
「道具を作る意味があった」と言える。1つ目と2つ目は、3つ目を実現するために必要な土台。

## 登場人物(仮)

- **幹事**: 誰がどの車に乗るか(車割り)を決める人。この道具が直接の対象にするかは Day2 以降で決める。
- **運転者**: 車割りが決まったあと、自分の車の出発点を決め、同乗者を迎えに行く順番と時刻を決める人。
- **同乗者**: 運転者の車に乗る人。自分の住所を入れる。

## やらないこと(いまは)

- 車割りそのもの(誰がどの車に乗るか)を決めること。**これは幹事が別の手段で先に決めている前提。**
- 複数台の車同士の調整(「A車とB車、どちらが先に出るか」など)。まずは1台の車の中で完結させる。
- 復路(帰りの送り)の計画。
- 割り勘や費用の計算。

範囲を広げたくなったら、新しい Issue にする。

## Hotspot(疑問・揉めごと)

- 車割り(幹事の作業)と、この道具の範囲の境目をどこで引くか。
  → Day2 のイベントストーミングで、車割りのあとから始まる前提で一度やってみて、違和感が出たら見直す。
- 「期日が近づいたら」とは、具体的にいつか(前日? 当日の朝? 時間ベースか距離ベースか)。
  → 使ってみて決める。最初は「当日の朝」で仮置きし、Day2 以降で具体化する。
