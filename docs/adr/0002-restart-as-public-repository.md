# 0002. 前身のリポジトリから作り直し、公開リポジトリにする

- 日付: 2026-10-11
- 状態: 採用
- 関連: なし（着手時の決定）

## 状況

この道具には前身のリポジトリ（非公開）がある。そこでは Rust で作る前提で、
足場（ツールチェーンの設定）と、設計の進め方の文書と、Issue 1件だけがあった。コードはまだ無かった。

その後、次のことが変わった。

- 技術を Rust から TypeScript に変える（[0003](0003-typescript-nestjs-svelte.md)）。
  **足場はほぼ全部捨てることになる。**
- 前身は、複数人で共有するサーバーで開発する前提だった。その制約もなくなった。
- 作る様子を YouTube で公開することにした。**ソースコードも見せたい。**
- 前身リポジトリは、発信用ではない個人のアカウントで作っていて、コミット履歴にもその名前が残っている。

## 決定

- **新しいリポジトリを、発信用のアカウント（`kkaiz-dev`）で公開で作る。**
- **前身の履歴は持ち込まない。** 中身（考えたこと）だけを書き直して引き継ぐ。
- 前身リポジトリは消さずに、読み取り専用（アーカイブ）にする。

引き継ぐもの：

| 中身 | 新しい行き先 |
|---|---|
| ペイン、肩代わりする3つ、当日のズレ（アクアライン） | Day 1 の `docs/design/00-why.md` |
| ユースケースの候補5件 | Day 1〜2 の材料 |
| 「ログインを作らず、共有 URL のトークンで権限を表す」案 | ADR の候補（未決） |
| 「保存先に Neon を使う」案 | ADR の候補（未決） |
| ルールと例（積み込み 5分、到着希望 7:00 → 出発 6:20 など） | BDD の Day の材料 |
| 設計の進め方 | `docs/README.md`（イベントストーミングと DDD の段を足した） |
| Issue・ブランチ・コミット・PR・ADR の運用 | `CONTRIBUTING.md`（Day の回し方を足した） |
| GitHub Flow の判断 | [0001](0001-github-flow.md) |

## 検討して選ばなかったもの

- **前身をそのまま公開に切り替える。** 個人の名前が履歴に残っているので不可。
- **前身の履歴を書き換えてから公開する。** 書き換えの漏れが怖いうえに、
  引き継ぐ価値のある履歴（コード）がそもそも無い。
- **前身で続けて、公開しない。** ソースコードを見せられないと、公開する意味が半分になる。

## 結果

できるようになること：

- 動画でソースコードをそのまま見せられる。
- Day 1 を空のリポジトリから始められる。

捨てたもの：

- **前身のコミット履歴と、Issue #1 の番号。** 経緯を辿りたいときは、前身のアーカイブを見る。
- **前身の ADR 0002（共有サーバーで Rust を動かすための工夫）。** 前提ごとなくなったので引き継がない。
- **前身で予定していた ADR 3枚**（Neon、domain を wasm でも使う、共有トークン）。
  wasm は 0003 で捨てた。残り2つは、その判断が必要になった Day で改めて書く。

見直す条件：

- なし。履歴を分けた判断は戻せない。
