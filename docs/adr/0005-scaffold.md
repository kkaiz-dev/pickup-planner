# 0005. 足場（Node.js・パッケージ管理・テストランナー）

- 日付: 2026-10-21
- 状態: 採用
- 関連: [0002](0002-typescript-nestjs-svelte.md)（TypeScript/NestJSを使う判断の続き）

## 状況

`api/` の最小限のプロジェクトを作り、TDD を回せる状態にしたい。
決めることは3つ。Node.js のバージョン、パッケージ管理、テストランナー。

## 決定

| | 選んだもの | 理由 |
|---|---|---|
| Node.js | **v24(LTS)** | 開発機にすでに入っている。個人開発でバージョンを揃える相手がいないので、入っているものをそのまま使う |
| パッケージ管理 | **npm** | Node.js に同梱されていて、追加のインストールが要らない。1人の個人開発で、pnpm のワークスペース機能(モノレポ向け)を使う場面が無い([ADR-0003](0003-repository-layout.md)でモノレポを捨てた判断と同じ理由) |
| テストランナー | **Vitest** | TypeScript・ESM をそのまま扱え、設定が軽い。ドメイン層のテストは高速に何度も回すので、起動の速さを優先した |

`api/src/domain/` から着手する。NestJS 本体(API のプレゼンテーション層)は、
ドメイン層ができて HTTP で公開する必要が出てから足す。

## 検討して選ばなかったもの

- **pnpm / yarn。** モノレポのワークスペース機能や、インストール速度の違いが効くのは
  複数パッケージを抱えるときで、今の `api/` 単体の規模では差が出ない。
- **Jest。** NestJS のデフォルトだが、ESM との相性で設定が増えがち。ドメイン層だけなら
  Vitest の方が足場が軽い。NestJS 本体を足すときに、プレゼンテーション層だけ Jest を
  検討してもよい(混在は許容する)。

## 結果

できるようになること:

- `npm test` でドメイン層のテストを高速に回せる。
- 追加のツールインストールが要らない(Node.js が入っていればよい)。

捨てたもの:

- pnpm のワークスペース機能、インストール速度。
- Jest と NestJS の既定の組み合わせ(ドメイン層については)。

見直す条件:

- NestJS 本体を足すときに、テストランナーを Jest に統一するかどうかを再検討する。
