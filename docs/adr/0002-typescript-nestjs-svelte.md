# 0002. TypeScript で作る（API は NestJS、フロントは Vite + Svelte）

- 日付: 2026-10-11
- 状態: 採用
- 関連: なし（着手時の決定）

## 状況

言語とフレームワークを決める必要がある。前提：

- 開発者は1人。開発環境は Mac。
- 本命の価値は「期日が近づいたら渋滞を反映して再計算し、全員に知らせる」こと。
  **定期実行・外部 API・通知が中心で、速さはほとんど効かない。**
- フロントで計算する必要がない。計算は API に任せて、フロントは表示するだけでよい。

## 決定

| | 使うもの | 配置 |
|---|---|---|
| 言語 | **TypeScript**（フロントもバックも） | |
| API | **NestJS** | Cloud Run |
| フロント | **Vite + Svelte + TypeScript**（PWA。SPA） | Cloudflare Pages |
| 経路 | Google Maps Routes API | API からだけ呼ぶ |

- 計算は API のドメイン層に置き、**フロントでは計算しない。**
- フロントとバックの境目は、共有コードではなく **API の契約**で持つ。
- ドメイン層（`api/src/domain/`）は NestJS にも外部 API にも依存させない（`docs/README.md` の 10）。

## 検討して選ばなかったもの

- **SvelteKit。** 強みはサーバー側の描画とサーバー側の処理。
  サーバーの役割は NestJS が全部持つので、重なるだけになる。静的な SPA で足りる。
- **共有パッケージ（`packages/domain`）でフロントとバックが同じ型を使う。**
  フロントが計算しないなら不要。共有すると、片方の都合でもう片方が壊れる。

## 結果

できるようになること：

- 言語が1つになり、足場・CI・テストの書き方が1通りで済む。
- ドメイン層を純粋な TypeScript で書けば、速くて壊れないテストで TDD を回せる。

捨てたもの：

- **オフラインでも計算できる道。** フロントが計算しないので、電波がないと何も出ない。

見直す条件：

- フロントで計算しないと困る場面が出たとき（電波の届かないゴルフ場の駐車場など）
  → そのときは計算の一部だけを共有パッケージに切り出すことを検討する。
