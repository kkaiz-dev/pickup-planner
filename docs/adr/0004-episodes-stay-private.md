# 0004. 動画の台本・スライドは、公開リポジトリに置かない

- 日付: 2026-10-12
- 状態: 採用
- 関連: [0003](0003-repository-layout.md)（`docs/episodes/` の記述を更新する）

## 状況

[0003](0003-repository-layout.md) では、`docs/episodes/` に動画の台本とスライドを置く想定だった。
実際に Day0 の台本を作ってみて、考え直した点がある。

- **YouTube はこのアプリの本筋ではない。** 開発そのものの記録と、動画という発信の形式は別物。
- 台本には、失敗談や個人の実体験など、**公開を前提にすると書きにくい内容**が入る。
- 他の kaiz_fire のシリーズ(月次資産公開、脱出の哲学)は、台本をどれも非公開の場所
  (`~/work/youtube`。push 先を持たないローカルだけの git)で管理している。
  開発ログだけ公開リポジトリに置くと、シリーズ間で扱いが割れる。

## 決定

**動画の台本・スライド・PDF・mp4 は、pickup-planner に置かない。**
すべて `~/work/youtube/episodes/<project>_dayNN/` で管理する。動画が公開されたあとも、ここには置かない。

- pickup-planner に残すのは、**PR・ADR・docs/design/**。動画の材料として参照はするが、
  台本そのものはこちら側に書かない。
- [0003](0003-repository-layout.md) のフォルダ構成図にある `docs/episodes/` は、この ADR で無くなった。
  0003 の本文は書き換えず、この ADR で上書きする。

## 検討して選ばなかったもの

- **動画が公開されたあとだけ、台本も pickup-planner に取り込む。** 二段階の運用になり、
  「今どちらの状態か」を毎回確認する手間が増える。シンプルに「ずっと非公開」で統一した。
- **`docs/episodes/` を残しつつ `.gitignore` する。** ローカルには残るが、他のマシンで
  作業するときに引き継げない。版管理そのものを外に出す方が筋が良い。

## 結果

できるようになること:

- 動画の台本に、公開前提では書きにくい内容を気兼ねなく書ける。
- 他の kaiz_fire シリーズと、台本の扱いが揃う。

捨てたもの:

- **「動画の台本もこのリポジトリで一元管理する」という、0003 で考えていた形。**
- 動画の制作過程も Day の PR から追える、という透明性(PR の「決めたこと」止まりになる)。

見直す条件:

- 動画の台本も公開してよいと判断したとき(→ この ADR を置き換える新しい ADR を書く)。
